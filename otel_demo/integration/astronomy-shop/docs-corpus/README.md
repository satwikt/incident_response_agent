# Documentation Corpus

Generated by `tools/build_corpus.py` from:

- the pinned vendor checkout at `85c2cb253ae3519ef2b3a02984c32614106de5ea`;
- every `src/*/README.md` component document;
- the vendored feature-flag definition (`src/flagd/demo.flagd.json`);
- the Copilot-owned docs under `docs/` (architecture, requirements, contract, plan, decisions, scenarios, runbook).

No network access is required.

## Files

- `corpus.jsonl` — one JSON chunk per line.
- `manifest.json` — document inventory, provenance, and totals.

## Chunk schema

| Field | Meaning |
|---|---|
| `id` | Deterministic chunk id (`<doc_id>:<ordinal>:<sha8>`) |
| `doc_id` | Source document identifier |
| `title` | Document title plus section heading |
| `heading` | Section heading (empty for preamble) |
| `text` | Chunk text, at most 1800 characters |
| `service` | Owning service/component, or `copilot-integration` |
| `source` | `vendor`, `local`, or `generated` |
| `source_url` | GitHub blob URL at the pinned commit, or `null` for local docs |
| `source_path` | Workspace-relative path |
| `app_version` | First 12 characters of the pinned commit |
| `tags` | Retrieval hints |
| `sha256` | SHA-256 of `text` |

## Regenerate and verify

```bash
cd integration/astronomy-shop
python3 tools/build_corpus.py
python3 tools/build_corpus.py --check
```

`--check` exits non-zero when the committed corpus is stale relative to the sources. The unit tests run the same check.

## Retrieval

`tools.build_corpus.search(records, query)` is a deterministic term-overlap helper used only to validate the corpus. This test module does not include a Copilot documentation indexer; a separate Copilot integration may use the corpus as an input artifact.
